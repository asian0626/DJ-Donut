# DJ Donut v2.1.0

2026-11-20 · [English](#english) · [繁體中文](#繁體中文)

## English

Version 2.1.0 addresses the playback, permission, reconnection, Spotify, storage, and diagnostic issues identified in the code review.

### Fixes and improvements

- **Playback consistency:** serialize playback and audio controls per room. Validate the current request after asynchronous resolution, invalidate stopped requests and old audio callbacks, and prevent simultaneous requests from showing one song while starting another. Queue capacity is checked again when enqueueing.
- **Safer dispatch:** reserve a bot while `/play` is connecting/resolving and prevent an explicit bot selection from taking over another occupied room. Reconnection requests reuse the existing SDK recovery instead of starting a second connection.
- **Shared control permissions:** require the same voice room and the existing DJ policy for playback-changing card controls. Extend DJ checks to shuffle, autoplay, 24/7, bass boost, and EQ commands. Opening a voice channel's text chat no longer counts as joining voice.
- **Bounded voice recovery:** preserve the current song, queue, position, and pause state while observing SDK reconnection for up to 35 seconds. Restore the native stream after connection recovery. Explicit stops, confirmed kicks, failed recovery, and shutdown follow their cleanup paths; no automatic rejoin is forced after a confirmed kick.
- **DAVE compatibility:** a missing target channel raises an actionable error instead of silently reporting handshake success. The compatibility patch checks the discord.py version, and requirements constrain it to the verified 2.7 series.
- **FFmpeg failure protection:** require an initial audio frame before treating native playback as started; stop empty/no-audio starts and reset consecutive failures only after startup succeeds. Explicit stop reasons make cleanup easier to distinguish from source failures.
- **Spotify correctness:** paginate playlist/album responses up to the existing 200-track import limit; reject collection-title-only HTML and yt-dlp fallbacks. API, public metadata, and extractor stages share a 25-second overall budget; failed resources are cached for 120 seconds. API retries and request timeouts are bounded, and logs include resource, status, track count, and elapsed time.
- **Bounded background work:** media extraction and metadata use separate pools. Waiting and execution share the caller's deadline. A timed-out running thread retains its capacity until it really finishes, so retries cannot grow the executor queue without limit. Next-track preload no longer waits for lyrics retrieval.
- **Storage durability:** serialize flush snapshots and commits; retry transient SQLite failures without requiring another settings change, with backoff up to 30 seconds. Shutdown interrupts the backoff wait and performs the final flush.
- **Diagnostics:** use Native/Lavalink-compatible connection properties in `/diag`; expose recovery/pending-request state and recovery/timeout counters. Slash-only startup no longer declares unused text prefixes that trigger message-content warnings.
- **Runtime and CI:** `./start.sh --check` prints environment versions. The launcher accepts Python 3.10–3.14, prefers 3.12 for new environments, and preserves unsupported existing environments with instructions. CI adds mypy, shell syntax validation, Linux Python 3.10–3.14, and macOS Python 3.12/3.14.

### Upgrade

Keep your `.env` and `data/` directory. No database migration or new required environment variables are introduced. Existing Python installations must refresh dependencies:

```bash
git fetch origin --tags
git switch --detach v2.1.0
.venv/bin/python -m pip install -r requirements.txt
./start.sh --check
./start.sh
```

For Docker, select the tag and run `docker compose up -d --build` instead. Stop the previous bot process normally before restarting. Fresh Python installations can run `./start.sh` to create a supported virtual environment and install requirements.

### Verification and limits

147 local automated tests pass, including 42 additional regression cases. Ruff, mypy, shell syntax, and whitespace checks pass. Live Discord network recovery and Spotify's external access policies cannot be guaranteed by these tests. WebSocket/TLS interruptions may still cause a pause; private, personalized, or API-restricted Spotify resources may remain unavailable. Timeouts bound callers and submissions, not the lifetime of an already running Python thread.

## 繁體中文

2.1.0 針對程式檢查發現的播放、權限、重連、Spotify、儲存與診斷問題進行修正。

### 修正與優化

- **播放一致性**：每個房間的播放與音訊控制依序執行。非同步解析後重新確認請求，取消停止後的舊請求與音訊回呼，避免同時點歌造成歌曲與卡片狀態不一致；入隊時再次檢查容量。
- **安全分流**：`/play` 連線／解析期間預留機器人，明確指定機器人也不能搶走其他有人使用的房間。SDK 重連期間沿用既有恢復流程，不會因點歌建立第二條競爭連線。
- **共用控制權限**：改變播放的卡片控制需加入同一語音房並符合原本 DJ 政策；隨機打亂、自動接歌、24/7、重低音與 EQ 指令也補上 DJ 檢查。開啟語音頻道的文字聊天室不再等同加入語音。
- **有限時間的語音恢復**：觀察 SDK 重連最多 35 秒，期間保留歌曲、隊列、位置與暫停狀態，連線恢復後重建原生串流。主動停止、確認被踢出、恢復失敗與關閉各自清理；確認被踢出後不會強制重新入房。
- **DAVE 相容處理**：缺少目標頻道時明確報錯，不再假裝握手成功；修補會檢查 discord.py 版本，相依需求限定已驗證的 2.7 系列。
- **FFmpeg 失敗保護**：收到初始音訊資料才視為啟動成功，無資料的啟動會停止並計入失敗；成功後才重設連續失敗計數。新增停止原因，方便區分正常清理與來源失敗。
- **Spotify 正確性**：歌單／專輯分頁讀取至既有的 200 首匯入上限，拒絕只有集合標題的 HTML／yt-dlp 回退。API、公開資訊與解析器共用 25 秒整體時限，失敗資源快取 120 秒；限制 API 重試及請求時間，記錄資源、狀態、歌曲數與耗時。
- **背景資源限制**：音訊與中繼資料解析使用不同工作池，排隊與執行共用請求時限；已逾時但仍執行的執行緒會持續占用容量，避免重試造成無上限堆積。下一首預載不再等待歌詞查詢。
- **儲存可靠性**：flush 快照與提交依序執行，SQLite 暫時失敗會自動退避重試，最長間隔 30 秒，不必等下一次設定變更；關閉時中止退避等待並執行最後寫入。
- **診斷改善**：`/diag` 改用 Native／Lavalink 相容判斷，提供恢復與待處理請求狀態、重連／逾時計數。斜線指令啟動不再宣告未使用的文字前綴，減少 message-content 警告。
- **環境與 CI**：`./start.sh --check` 顯示執行版本；支援 Python 3.10–3.14，新環境優先使用 3.12，保留未支援的舊環境並給出提示。CI 新增 mypy、Shell 語法、Linux Python 3.10–3.14 與 macOS 3.12／3.14 驗證。

### 升級方式

請保留原本的 `.env` 與 `data/`，不新增資料庫遷移或必要環境變數。既有 Python 環境需更新相依套件：

```bash
git fetch origin --tags
git switch --detach v2.1.0
.venv/bin/python -m pip install -r requirements.txt
./start.sh --check
./start.sh
```

Docker 部署切換標籤後改用 `docker compose up -d --build`。重新啟動前請先正常停止舊行程；全新 Python 安裝可直接使用 `./start.sh` 建立支援的虛擬環境並安裝需求。

### 驗證與限制

本機 147 項測試通過，包含新增的 42 項回歸情境；Ruff、mypy、Shell 語法與空白檢查通過。測試無法保證實際 Discord 網路恢復或 Spotify 外部存取政策；WebSocket／TLS 中斷仍可能造成短暫停頓，私人、個人化或受 API 限制的 Spotify 資源仍可能無法取得。逾時限制的是呼叫方與提交量，不會強制殺掉已執行的 Python 執行緒。
